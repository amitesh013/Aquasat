# AquaSat architecture

```text
Sentinel-2 v3 optical images → clear95 NDWI/MNDWI threshold sweep
                 ↓ early-date rule selection by reservoir
Selected area rule + prior-only isotonic calibration → S2 storage estimates
                 ↓ later 20% holdout scoring
build_clear95_dashboard.py → dashboard_data.csv + metrics.csv
                 ↓
app.py → active satellite history and holdout accuracy panel
                 ↓
app.py ← reservoir_forecasts.csv ← generate_live_xgboost_forecast.py
                            (official history + prior satellite lag feature)

Sentinel-1 VV/VH backscatter candidates → early-date selection + later holdout
            → S2-first/S1-gap-fill satellite history → XGBoost forecast lag feature
            (S1 does not alter satellite storage cards or replace same-date S2 values)

IMD daily 0.25° rainfall grid → nearest reservoir-centre cell → prior 7/30/90-day totals
            → 2019 crisis and 2019–2024 backtests + app validation tab
            (research only; not connected to the live forecast)
```

## Technology stack actually present

| Tool | Actual purpose in this archive |
|---|---|
| Python | Extraction, data preparation, calibration experiments and forecasts |
| Google Earth Engine Python API | Satellite image processing in extraction scripts; rerun was not attempted because credentials/environment are absent |
| pandas / NumPy / SciPy / scikit-learn | Data handling, IMD NetCDF extraction, and calibration experiments |
| XGBoost | Active 15-day forecast generator; uses official storage history and an optional lagged calibrated satellite-storage estimate. The live source file prefers S2 and fills same-lake/date gaps with S1. Backtesting did not show a broad accuracy gain from S1. |
| Prophet | Experimental forecast comparison; does not drive the dashboard forecast |
| Streamlit / Plotly | Dashboard in `app.py`; packages are not included in the current runtime |
| CMWSSB website | Official reservoir storage reference; live form submission and scraper behavior have not been integration-tested |

The live forecast is generated by `generate_live_xgboost_forecast.py`; `forcast_reservoirs.py` delegates to it by default and preserves the prior seasonal/damped-trend baseline behind `--model seasonal-baseline`. The generator uses non-disputed official history and the combined S2-first/S1-fallback candidate as a lag feature. Its day-15 endpoint is model-generated, its daily display path is interpolated, and its residual band is approximate rather than a calibrated probability interval. The user selected the combined feature despite a 444-pair backtest showing no broad S1 gain (pooled RMSE about 210.84 mcft with S2 only versus 210.93 with S2/S1). Sentinel-1 is not an MNDWI input: it is C-band radar backscatter, measured with VV/VH thresholds and calibrated separately against exact-date official readings.

`build_imd_rainfall.py` reads the official IMD daily 0.25° NetCDF grid and produces nearest-cell daily rainfall proxies for each reservoir. `backtest_2019_rainfall.py` adds antecedent 7/30/90-day rainfall features to a separate historical XGBoost comparison, excluding rainfall on or after the forecast origin. On 344 exact-date 15-day targets in 2019–2024, pooled RMSE was 221.49 mcft without rainfall and 225.84 mcft with rainfall (capacity-normalized RMSE 10.46% vs 10.48%). Because the pooled result worsened and performance varied by year and lake, rainfall remains outside the live forecast. The app displays the separate 2019 case study and the multi-year scores. The selected grid cell is a local proxy rather than a watershed average; the experiments do not establish causal inflow effects.

## Reproduction boundary

The ZIP is missing `handwritten_ground_truth_clean.csv`, dependency files, and Earth Engine credentials/configuration. Calibration, extraction, and Streamlit launch therefore cannot be reproduced from this archive alone. Use Python 3.10+ with the script imports installed, run scripts from the project directory, and obtain the missing ground-truth source before rebuilding calibration outputs.
